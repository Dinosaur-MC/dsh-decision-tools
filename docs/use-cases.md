# `decision` 工具：使用场景（use cases）

> 与 `docs/architecture-current.md` 配套：那篇讲**是什么**，这篇讲**什么场景该用、怎么调、成本与边界在哪**。
> 事实基线：HEAD `549b057`（2026-10-15）· 套件 174/174 绿。

## 0. 判定形状（决定它适配哪些场景）

- 输入 = **一份共享材料** + **1–64 个有界问题**；输出 = 每题的概率 / 标签 / 分档。
- **不产文字**、不做推理链、不读图片。
- 适用前提三条：**候选集已知且有限**、**判据能写清**、**答案能用概率表达**。

## 1. 五类判定形状（主分类）

| # | 形状 | 典型场景 | 题型 | 材料怎么给 | 一次题数 | 当前 API 的手感 |
|---|---|---|---|---|---|---|
| 1 | **逐项二值筛选**（同判据判 N 项） | 文献/资料是否属于核心集 · 候选是否相关 · 告警是否真阳 · 工单是否需人工 · 段落是否含敏感信息 | `noul` | 材料=判据+规则；每项只带自己的标识或短文本 | 10–64 | **最别扭**：判据要抄 N 遍（真机 35 项实测：请求体 73% 是重复判据） |
| 2 | **同标签集归类**（N 项各自归一类） | 意图路由 · 工单/日志分类 · 渠道识别 · 失败原因归类 | `choice`（选项 undefined–255） | 同上 | 10–64 | 判据与选项集都要抄 N 遍 |
| 3 | **分档打分 / 排序** | RAG 重排 · 相关性分级 · 候选质量分档 · 风险等级 | `score`（档位 undefined–10） | 同上 | 10–64 | 档位描述要抄 N 遍 |
| 4 | **一材料多异质问题** | 一份合同问 5 个不同问题 · 一份报告问是否合规/是否含某字段/是否需复核 | 混合 | 材料=那一份；每题自己的 `instructions` | 2–10 | 手感尚可（本来就该每题一句） |
| 5 | **长材料定位**（哪些块提到 X） | 跨长文或多文件找相关段 · 大文档初筛候选段 | `noul` | `stateSource` 的 file/glob，或走 `scan` | 1–8 | `scan` 只答**可定位**问题；材料过大时自动分块 |

## 2. 材料来源的三种给法

| 给法 | 何时用 | 注意 |
|---|---|---|
| 内联 `state` | 材料小（几百字节）且本就在上下文里 | 每多一份材料就多一份请求体 |
| `stateSource{kind:file}` | 材料在工作区文件里、**不想进自己的上下文** | 支持 1-based 行范围；单文件超上限**报错**不截断 |
| `stateSource{kind:glob}` | 一批文件要一起判 | `*` 不跨目录、`**` 任意深度；总量超上限**截断**并报 `truncated`/`remaining` |

## 3. 场景 → 调用骨架

### 3.1 逐项二值筛选（35 条文献，真机案例）

现状（能跑，但判据被抄 35 遍）：

```jsonc
{
  stateSource: { kind: 'file', path: 'docs/开题报告.md', startLine: 233, endLine: 269 },
  questions: [ { name: 'r1', type: 'noul', instructions: '<判据全文> + 文献 [1]' }, … ]
}
```

实测代价：请求体 26056 B（73% 是判据）、`input_tokens` 282651（= 题数 × 请求体）、被推出小模型窗口被迫用 nimble。**注意该样例发生在 2026-10-13，当时 tev1:0.8b 的窗口是 2050**；窗口现为 8192，同样的形状不再必然触发升档——但「按题数重复计费」这一条与窗口无关，仍然成立。

v3 形状（判据只写一次）：

```jsonc
{
  material: { file: { path: 'docs/开题报告.md', startLine: 233, endLine: 269 } },
  rubric: '属于 lens/双向变换、结构化编辑、增量解析、块↔文本同步的直接来源 ⇒ true；背景铺陈/领域泛论/教学综述/可替代工具文档 ⇒ false',
  items: [ '文献 [1]', '文献 [2]', …, '文献 [35]' ],
  type: 'noul'
}
```

### 3.2 一材料多问（异质问题）

```jsonc
{ state: '<合同全文>',
  questions: [
    { name: '合规', type: 'noul', instructions: '是否含自动续约条款？' },
    { name: '风险', type: 'score', instructions: '风险等级', criteria: [ '低', '中', '高' ] } ] }
```

### 3.3 长材料定位（走扫描）

```jsonc
{ stateSource: { kind: 'glob', pattern: 'docs/**', limit: 20 },
  strategy: 'scan', aggregate: 'any',
  questions: [ { name: '提到X', type: 'noul', instructions: '本段是否提到 X' } ] }
```

`aggregate` 的逐块最大值只作定位线索，**不是**文档级结论。

## 4. 成本与窗口：决定「一次能问多少」

- **计费 = 题数 × 请求体**（已实测：`input_tokens = Σ prompt_k`）⇒ 重复判据被乘 N 次；
- **窗口**（`num_ctx`，2026-10-15 实测）：tev1:0.8b num_ctx                        8192 · tev1:latest num_ctx                        8192 · clef-flash:latest num_ctx                        16384 · nimble-v3:latest num_ctx                        32768 · nimble:latest num_ctx                        8194 · clef:latest num_ctx                        16384；默认阶梯现为 tev1:0.8b → tev1:latest → clef-flash:latest → nimble-v3:latest；
- **字节换算**：英文 3.33 B/token，**中文实测 2.32 B/token** ⇒ 中文材料要按更小的字节数留余量；
- 结论：项数多时要么**判据只写一次**（v3 形状），要么**拆批**；`scan` 救的是材料太大，**不救题数太多**。

## 5. 反场景（不要用它做这些事）

| 不要做 | 理由 | 替代 |
|---|---|---|
| 开放式生成、写文案、出摘要 | 它**不产文字**，只回概率 | 生成式模型 |
| 需要推理链、多跳计算 | 不做逐步推理 | 生成式模型 + 明确步骤 |
| 需要**可读判据**作为证据存档 | tev1 系只回概率 | 生成式模型，或人写结论 |
| 路由 / 放行的**最终判据**（fail-open/closed） | 概率不是证明；模型坏了会连带坏掉路由 | 确定性规则；本工具只做初筛 |
| 对整篇长文问**整体**结论并交给 scan | 逐块最大 ≠ 文档级概率 | 先 scan 定位候选段，再对候选段单发提问 |
| 图片 / 视觉判定 | 非目标 | 视觉模型 |
| 把结果当**正确性证据** | 概率是提示不是证据 | 产物级证据 |

## 6. 场景 × API 适配度（v3 的验收标准）

| 场景 | 现状要写多少重复 | v3 之后 |
|---|---|---|
| 逐项二选一（N 项同判据） | 判据 × N | **判据 1 份 + N 个 item**（形状上不可能重复） |
| 同标签集归类（N 项） | 判据 × N + 选项集 × N | 判据 1 份 + 选项集 1 份 |
| 分档打分（N 项） | 判据 × N + 档位 × N | 同上 |
| 一材料多问 | 本来就不重复 | 保持（`questions` 与 `items` 并存） |
| 长材料定位 | 不需要重复 | 保持；批大小由插件按 body 预算决定 |
