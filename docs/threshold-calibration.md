# 阈值标定、粘滞优先级与运行时能力发现

> 口径文档（2026-10-16）。依据：`docs/architecture.md` §4（成本与容量口径，含 §8 r6 真机数字）、
> `docs/superpowers/plans/2026-10-16-v3-improvement-plan.md` Task 17、用户裁定 R1（显式 model 与成功升档都写粘滞）。
> 本文只写**方法与口径**：任何阈值都必须在你自己的标注集与业务上重新标定，本文不给「通用阈值」。

## 1. 为什么必须按 (模型 × 题型 × 业务) 标定

- `confidence` 是分布集中度（`1 - H(p)/ln N`），**不是正确率**；同一个数值在不同模型上不是同一件事 ——
  既有观测：同一批题 `tev1:0.8b` 落在 0.04–0.62，而 4B 及以上的四个模型落在 0.77–0.99
  ⇒ 默认门限 0.25 在 4B+ 上**是惰性的**（永远不会触发）。
- **换档即换基座**：升档后模型不是同一个模型，为旧模型标定的门限不再自动成立。
- 概率本身会随**判据位置**与**选项排列**漂移（r6：位置 mean|ΔP| = 0.0208、max = 0.2236；
  顺序诱发的标签翻转是 `tev1:0.8b` 独有现象）。

⇒ 标定对象是**三元组**（模型, 题型, 业务），不是「这个插件」。换其中任何一个都要重标。

## 2. 标定方法（可照做）

### 2.1 数据集

- 每个 (模型, 题型, 业务) 分组准备带 **ground truth** 的样本，从**生产分布**里抽，不要用合成集代替。
  （建议下限，非实测结论：每组 ≥30 题，且**必须包含你真正不敢放错的那一类**。）
- 每题至少复现 2 种**排列**：`noul` 的键序、`choice` 的选项序。把「标签是否翻转」单独记一列 ——
  翻转率高的题型本身就不适合自动化放行。
- 复跑同一条件应逐位一致（惰性模型）；不一致说明装置或模型不稳定，先查装置。

### 2.2 报告什么

| 项 | 口径 |
|---|---|
| 标签一致率 | 多种排列下标签相同的题数 / 总题数 |
| 分组正确率 | 与 ground truth 比，按 (模型, 题型, 业务) 分组报，不报全局平均 |
| 校准曲线 | 把 `probabilities` 分箱（如 0.0–0.1 … 0.9–1.0），比较**箱内实际命中率**与预测均值；偏离对角线 ⇒ 不能当概率用 |
| 阈值曲线 | 扫门限 t，对每个 t 同时报「漏判高风险」与「误选无害」两个计数 |
| 期望成本 | 给两类错误各一个业务代价权重，选**期望成本最小**的 t —— 不是选「错误率最低」的 t |

### 2.3 两类成本不得共用一个阈值

- **漏判高风险**（把该拦的放过去）：代价常常不可逆 ⇒ 取**低**门限 + 强制复核。
- **误选无害**（把无害的拦下）：代价只是可容忍的返工 ⇒ 可用**高**门限自动放行。
- 一个 t 同时服务两类，等于把无害类的宽松度借给高风险类。⇒ 至少两个阈值，或按题型/业务各自一个。

### 2.4 低置信项的去向（成本递增）

1. **换更大档复核**（本插件内：显式 `model`，或用 `depth: 'deep'` 起步）—— 注意换基座，
   复核用的门限要**单独标定**；
2. **生成式模型复核** —— 需要**可读判据**留档时唯一的选项（tev1 系只回概率、不产文字）；
3. **人工 / 确定性规则** —— 最终放行判据必须落在这一层，不在本插件（概率是提示不是证据）。

### 2.5 已有观测（是观测，不是阈值结论）

- `minConfidence` 默认 0.25 来自一次小样本标定（`tev1:0.8b`，4 题 × 6 种排列）；跨模型差一个数量级，
  换模型必须重标。
- 跨会话研究里唯一一次顺序诱发的标签翻转落在 `confidence = 0.357`（**高于** 0.25）⇒ 该门限
  **不是**安全保证，只是「把最差的那些点出来」的旗。
- 出处：`docs/architecture.md` §4 与 `README.md` 的 `minConfidence` 段；这些数字属于**当时样本**，换模型/换业务要重测。

## 3. 粘滞：三层优先级与失效条件

优先级（高 → 低）：

1. **显式 `model`（本次调用）** —— 一律赢（含向下降级）；按用户裁定 **R1**，显式值**写进进程粘滞**。
2. **进程粘滞** —— 上一次显式指定、或上一次**成功**升档后的模型。
3. **默认档**（`Config.defaultModel`）。

补充规则（现状实现的准确读法）：

- A 方案（用户 2026-10-13 裁定）之后，**日常选档由容量分派 `selectByCapacity` 决定**：按本次材料
  估算需求，取「容量够用的最小档」。粘滞只在容量分派给不出答案时兜底（阶梯为空 / 容量未知），
  `reason` 为 `sticky-fallback`。
- **只有确认可用才写粘滞**：升档失败不得粘滞，也不得改写本次生效的模型。
- 粘滞**不因 `defaultModel` 变化而回退** —— 防 A 要小档 → B 升档 → A 又要小档 的反复冷加载。

失效条件：

| 条件 | 效果 |
|---|---|
| 显式传 `model` | 立即改写粘滞（本次即用该模型） |
| 模型不存在 / 不被端点支持 | 该档不得粘滞；按配置换档或如实报错（`<model> does not support decision` 一律 400） |
| 本次请求溢出（容量类失败） | 触发下一档；**只有确认成功**才粘滞 |
| 用户再次显式指定 | 覆盖前一次粘滞 |

**跨任务影响范围**：粘滞住在插件进程里，**同一进程的所有调用共享**。长任务（或一次 `deep`）把它推到
16 K / 32 K 档之后，**之后所有轻量调用也会用大档** —— 实测小材料打大档是默认档的 **7–9 倍慢**，
但绝不退档（这是刻意的防抖）。⇒ 想让一次重活不影响后续轻量调用，就给它显式 `model`（或反过来，
给轻量调用显式指定小档）。

## 4. 运行时能力发现：什么能探测、什么不能

| 能力 | 能否本地探测 | 权威来源 | 插件行为 |
|---|---|---|---|
| 模型窗口 `num_ctx` | **能**：`POST /api/show`（本机实测约 125 ms，读 `parameters` 段） | `/api/show` | 优先用探测值；**探测失败才回退静态值**（`DEFAULT_LADDER` / `Config.ladder` 的快照，会随模型重拉失效） |
| 模型可用性 / 能力 | 能：`/api/tags`、`ollama show` 的 `capabilities` | 同上 | 只用于判断「该模型不是 decision 模型」（服务端 400 `<model> does not support decision`） |
| **题型上限**（`choice` 选项数 / `score` 档位数） | **不能**：本机 `/openapi.json`、`/swagger.json`、`/docs` 一律 **404**（2026-10-16 实测），无机器可读规格 | **服务端 400** | `LIMITS.maxChoiceOptions = 255` 只是「不预先拒绝」的**宽松默认** + `Config.maxChoiceOptions` 覆盖点；收到题型相关 400 时如实透传原文（`too many options (256), this model supports at most 255`） |

- **口径注（官方文档自身不一致）**：官方决策指南写 `choice` **2–26 named options**，官方 API 参考写
  `SystemOneChoiceQuestion.criteria` 的 `maxProperties: 255` 并注明 *"The option limit depends on the model"*
  （抓取件与行号见 `docs/architecture.md` §4 的口径注）。⇒ **不得声称插件能本地探测题型上限**；
  也不要把 255 或 26 当跨版本 / 跨模型契约。
- `score` 的 2–10 是与 `choice` **相互独立**的约束，不可共用一个常量。
- 顺序固定为：**运行时能力 > 静态常量**。探测成功即用探测值；探测失败才回退，且回退值必须标注为快照。
